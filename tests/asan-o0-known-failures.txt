# Fixtures that FAIL the memory_sanitizer suite at KARAC_OPT_LEVEL=0 and PASS
# at the default -O2. Consumed by scripts/asan-o0-leg.sh. B-2026-08-04-17.
#
# Every entry names the bug row that owns it. Nothing goes on this list without
# one — an unattributed entry is indistinguishable from a fixture someone
# silenced.
#
# THE LIST ONLY SHRINKS. scripts/asan-o0-leg.sh fails both when an unlisted
# fixture starts failing (a regression) and when a listed one starts PASSING
# (the owning bug got fixed and the line is now stale). That second direction is
# what keeps this from decaying into a permanent allowlist.
#
# These are NOT -O0-only curiosities dismissible as debug-build noise. At -O0 no
# pass pipeline runs, so the allocations the fixture intends actually happen;
# at -O2 the same buffers are provably dead and LLVM deletes them, which is why
# the fixture passes there. The leak is in the emitted code either way — -O2
# just deletes the evidence along with the allocation.
#
# Measured 2026-08-06 at 225a4553, x86_64 Linux, both archives rebuilt
# lean-then-full: 942 passed / 4 failed / 10 ignored in 92s.
#
# THE LIST IS NOW EMPTY (2026-08-06). All four entries are fixed, each removal
# recorded below with the mechanism rather than deleted silently. The leg still
# gates: with nothing quarantined, ANY -O0 failure is a new failure.

# B-2026-08-06-2's entry (asan_generic_struct_heap_field_move_out_no_double_free)

# predicate (B) two commits later, so the line was stale on arrival. The ratchet

# "a listed fixture that starts PASSING fails the leg too" direction intends.

# B-2026-08-05-7's tensor entry (asan_tensor_lifecycle_clean) was REMOVED
# 2026-08-06: the fresh-temp owned-argument leak it named is fixed. Owned tensor
# params are caller-retains like Vec/String, and the caller-side materialization
# that covers those is gated on the Vec `{ptr,len,cap}` LLVM shape, which a
# tensor — a bare `ptr` to one `[rank][dims][data]` block — is not. It now gets
# its own caller-scope `FreeTensor` behind the same passthrough guard.
#
# Not an -O0 curiosity either: with a callee that reads the WHOLE block
# (`t.sum()` rather than `t[0, 0]`) the leak measures 2,240 B / 40 blocks
# IDENTICALLY at -O0 and at the default -O2. The fixture read it one element at
# a time, which is what let LLVM delete the allocation and made it look
# -O0-only. `asan_tensor_fresh_temp_owned_arg_no_leak` carries the summing form
# so the default leg gates it too.

# B-2026-08-05-7's nested-Option entry
# (asan_nested_option_pattern_boxed_payload_lifecycle_clean) was REMOVED
# 2026-08-06: all three of its boxes now have owners. Its old line here read
# "`Wrap.W(Option.Some(s))` orphans the box; the control that never matches it
# out is clean" — that attribution was wrong and is worth recording, because it
# pointed at the wrong site. The box leaks on CONSTRUCTION: the same value
# matched with a bare `_` leaks identically (measured 288 B / 9 at HEAD before
# the fix). The fixture's "clean control" is a different VALUE — a named
# `Option[Option[String]]` whose let-site box drop does own its box — not the
# same value left unmatched.

# B-2026-08-06-10's entry
# (asan_shared_payload_view_optres_field_call_arg_copy_no_leak_no_double_free)
# was REMOVED 2026-08-06: the last entry, so THE LIST IS NOW EMPTY and any -O0
# failure from here on is a new failure.
#
# Its line here had been re-attributed from B-2026-08-05-7 after isolation, and
# the version before that is worth remembering as a caution — it read "an
# `Option[H]` field read out of a shared-enum payload and passed BY VALUE to a
# free fn", naming three things that all turned out to be irrelevant. Measured
# one variable at a time, the only one that moved the result was whether the
# CALLEE's arm returns `x.label` (leaked) or `x.k` (clean).
#
# The fix is three paired sites — caller stays armed for a boxed payload, callee
# mirrors its move-out THROUGH the box, and the shared-view defensive clone gets
# a caller-scope owner. Each alone is a different bug: the first two are a double
# free without each other, and the third was invisible in the reduction (it is
# what the fixture's remaining 64 B turned out to be, a second leak of exactly
# the same size hiding behind the first).

# B-2026-08-07-12 — asan_struct_field_boxed_payload_interior_match_out_no_double_free
#
# ADDED 2026-08-07 under B-2026-08-07-7, RE-ATTRIBUTED the same day once that
# row's own residue was fixed and the line did not go away. Both halves of the
# history are worth keeping, because the re-attribution is the interesting part.
#
# The fixture's shape DOUBLE-FREED at both opt levels: a match arm binding the
# interior out of a struct field whose `Option` payload is heap-boxed, where the
# struct's deep drop frees the same `String` the arm's binding owns. c25c949
# zeroes the field's tag so that drop skips the field — but that one tag guard
# also gates the box free, so the 32-byte ENVELOPE leaked in the consuming case.
# That was the original entry, and B-2026-08-07-7 predicted that giving the
# envelope an owner would remove this line.
#
# It did not, and the arithmetic says why. At -O0 the fixture went 7,680 B over
# 240 blocks to 5,120 B over 160: the 80 envelopes are gone — two consuming
# sites (`bound`, `whole`) x 40 iterations — and 160 blocks remain. Those belong
# to a defect that was inside this fixture all along: every one of its FOUR
# by-value calls per iteration orphans the CALLER's box, because the callee's
# entry copy duplicates the box and shares the `String` inside it. That
# reproduces with a non-consuming arm, with a callee whose body is `1`, and with
# c25c949 stashed. It was filed as B-2026-08-07-12.
#
# B-2026-08-07-12's fix then took it from 5,120 B / 160 to 1,280 B / 40, and the
# 40 that remain are a THIRD reason — so this one line has now outlived three
# distinct causes, which is exactly why the list requires an explanation per
# entry rather than a bug id alone.
#
# What is left is `scalar(V { o: Option.Some(Option.Some(n + i)) })`, whose
# payload is ALL SCALAR. The caller-scope gate declines it correctly by its own
# standard — there is no heap inside the `Option` — but the 32-byte ENVELOPE is
# itself heap, and nothing owns it. That is the envelope-ownership question
# B-2026-08-07-6 / -11 are about, reached here through a by-value struct
# argument, and it is tracked as the remaining leg of B-2026-08-07-12.
#
# The lesson for the next attribution: a fixture written to exercise one row can
# fail for a second row's reason, and "my fix should have emptied this line" is
# a prediction to MEASURE, not to act on. The envelope fix is pinned separately
# by asan_struct_field_boxed_payload_match_out_envelope_owned, which uses only
# local places precisely so no by-value call can contaminate it.
#
# Two rejected alternatives from B-2026-08-07-7 stay recorded there so a future
# attempt does not re-walk them: making the drop box-only unconditionally costs
# five passing sanitizer tests, and firing the suppression on any consuming
# pattern (rather than a nested variant one) orphans 504 B in
# asan_b04_7_option_heap_enum_struct_field_drop.
