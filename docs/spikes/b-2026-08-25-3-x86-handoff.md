# B-2026-08-25-3 — x86_64 leg (the leg that actually matters)

The one OBSERVED failure was x86_64. Everything measured on the M5 Pro is arm64
and, per the row's arch-asymmetry note (B-2026-07-12-29 is this repo's proof an
arm64-only memory-class defect exists), cannot clear it.

## Order of work — targeted FIRST, not the full suite

The row's original recipe says "loop the full suite". On x86 do the targeted
probe first. Reason: the full suite yields ~2.4 samples/hour against a
hypothesis about EMITTED CODE, while the targeted probe recompiles all six guard
programs from source in ~1.7s -> ~2000 invocations/hour (~12,000 programs/hour).
It is ~800x more evidence per CPU-hour on exactly candidate (b).
The full suite is still the ONLY instrument for a flake that needs full-suite
CONDITIONS, so run it second, not never.

## 1. Archives — ALL EIGHT, lean before full

Both lean and full emit the canonical name, so order matters; gpu/regex/arrow/
unicode each clobber it and must be renamed then the plain full build restored.
See CLAUDE.md "Codegen E2E + memory_sanitizer require the runtime library".
VERIFY, do not assume:

    nm -g target/release/libkarac_runtime*.a | grep -c karac_runtime_install_stack_guard

A MISSING archive is not cosmetic here: `KARAC_REQUIRE_RUNTIME_ARCHIVE=1` turns
it into a hard failure (good), but WITHOUT that var the guard test's
`None => return` soft-skip makes it PASS while asserting nothing.

## 2. Targeted probe

    cargo test --release --features llvm --no-run
    BIN=./target/release/deps/codegen-<hash>
    T='codegen_tests::vec_mutation_methods_bounds_check_out_of_range_index'
    for i in $(seq 1 5000); do
      out=$(KARAC_REQUIRE_RUNTIME_ARCHIVE=1 "$BIN" "$T" --exact 2>&1)
      printf '%s' "$out" | grep -q "^test result: ok\. 1 passed" || {
        echo "HIT $i"; printf '%s\n' "$out" > HIT_$i.log; }
    done

`ok. 1 passed` -- NOT `ok.` -- see trap 4.

## 3. Full-suite loop, second

    HDR='---- codegen_tests::vec_mutation_methods_bounds_check_out_of_range_index stdout ----'
    KARAC_REQUIRE_RUNTIME_ARCHIVE=1 cargo test --release --features llvm --no-fail-fast > r_$i.log 2>&1
    grep -qF -- "$HDR" r_$i.log && echo "HIT $i"

The `--` is load-bearing (trap 3). KEEP every log (trap 5).

## Traps that produce FALSE CLEAN readings

1. Bare test-name grep matches the PASS list too. Match the failure header.
2. Missing optional archive fails whole suites and buries the signal under noise.
3. `grep -qF "$HDR"` without `--`: the header starts with `----`, grep parses it
   as options, EXITS 2, and `if grep -q` reads that as clean. Cost: 5 iterations
   scored by a detector that never ran once.
4. `--exact` matching nothing prints `test result: ok. 0 passed` -- a zero-sample
   run scoring as a pass. Require `1 passed`.
5. Deleting the per-iteration log on a "clean" verdict. Traps 3/4 mean the
   verdict can be wrong; keep the evidence.
6. ABSENCE OF THE FAILURE HEADER IS NOT PROOF THE TEST RAN. If the codegen
   binary dies (observed: SIGTERM), the suite reports no failure for a test that
   never executed and a header-only detector calls it clean. Assert the POSITIVE
   line `test <name> ... ok` per iteration, and sanity-check the suite's
   passed-count (a good codegen run is 3225; a killed one showed 10).

Negative-control any detector against {pass, zero-tests, FAILED, empty-output}
BEFORE trusting a clean run.

## How to read a hit

A hit after e647b5a CANNOT be a stale-artifact exec (per-process nonce +
pre-emptive unlink + post-link existence assert), so it is evidence FOR
candidate (b) and the row becomes HIGH severity.

Capture the EXIT STATUS, not just stdout/stderr -- the assertion currently
discards it, and the signal number is what identifies the death. Expect
`free(): invalid pointer` / exit 134 on glibc; macOS reports a malloc abort
instead, so match the SHAPE (no panic + allocator abort), not the glibc string.

Do NOT read "stdout empty" as "the program never ran": `println` -> `printf` ->
block-buffered pipe under `Command::output()`, so a program that printed
"survived" and then aborted shows EMPTY stdout.
