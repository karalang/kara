# Program corpus

Every runnable Kāra program the project has, as plain files, so that every
backend can be measured against the same expectations: the legacy interpreter
and AOT backend now, and the MIR pipeline as it lands (v2 plan, M0).

```
corpus/<area>/<name>/source.kara       the program
corpus/<area>/<name>/source.orig.kara  the program before `karac fix` or a hand edit (only when changed)
corpus/<area>/<name>/legacy.out        stdout of one run on today's compiler, recorded at extraction
corpus/<area>/<name>/expected.out      what the runner compares against
corpus/<area>/<name>/meta.toml
```

Areas:

| area | from |
|---|---|
| `fixtures/<suite>/<file>/` | raw-string programs with a `fn main` in `tests/**/*.rs`; `tests/codegen/strings.rs` gives `fixtures/codegen/strings`, `tests/cli.rs` gives `fixtures/cli` |
| `katas/<range>/<kata>/` | karalang/kara-katas |
| `examples/` | single-file `examples/*.kara` |
| `core/` | the core-semantics pinning programs (with `docs/core-semantics.md`) |
| `drop-matrix/<shape>__<position>/` | generated by `tools/drop-model/matrix.py`: value shapes x positions, expected output from the drop reference model (`tools/drop-model/model.py`) |

`<name>` is the test function (or `const`) holding the program, or the
kata/example file stem. A second distinct program in the same test gets `_2`.

## meta.toml

| key | meaning |
|---|---|
| `source` | `tests/<file>.rs::<test>`, or the kata/example path |
| `dedup_of` | every other test whose program text is identical |
| `expect` | `stdout`, `panic:<exit>`, `error:<code>` (`codegen` = any refusal), or `skip` |
| `exit` | expected exit code |
| `tags` | see below |
| `class` | `a`..`e` once classified against the MIR interpreter; `unknown` until then |
| `expected_from` | `assert` (the test's own string literal matches), `legacy-run`, `spec` (the drop model), or `pin` |
| `legacy_backend` | the backend today's suite used: `legacy-interp` for `tests/interpreter`, else `legacy-build` |
| `rules` | core-semantics sections the program pins |
| `backends` | empty = all; otherwise the only backends it applies to |
| `env` | extra environment for every run |
| `note` | free text |

Tags come from the source and from `karac check --output=json`: `drop`,
`shared`, `par`, `closure`, `ref-return`, `panic` (legacy exits 101),
`uses-moved` (E0500 / N0503), `move-from-borrow` (the `borrow_projection_copy`
and `for_element_drop_copy` lints), `deferred:<feature>` (GPU, tensors,
dataframes, comptime, `dyn`, layout blocks, `catch_panic`, `Regex`,
`normalize`), `bench` and `differential` for katas, `format-template` for
a raw string the test fills in at run time, with `format!` or by `push_str` onto
a `String::from` head (recorded as `skip`), and `nondeterministic` for a
program whose output changes between two legacy runs (a bound port, task
scheduling, cancellation timing; also `skip`). A raw string bound by `let` and
filled in with `.replace("KEY", "..")` is not a template: it becomes one
program per replacement, named `<test>__<variable>`.
Derived from the record without a run (`record.py --retag`): `needs-driver`
for a program whose legacy run timed out (almost always a server the Rust
test drives with a client), `literal-unmatched` for a fixture whose holding
test has string literals none of which equals the legacy stdout (an IR-shape
test, a partial assertion, or a pinned legacy bug; the first literal is in
`note`), and `class = "d"` for every `deferred:*` program. `record.py
--mirror` runs each kata's same-stem Python mirror and tags `mirror-agrees`
or `mirror-differs`; most differences are bench programs whose mirror uses a
different input or random stream, so a difference is a prompt to look, not a
verdict.

## Running

```bash
cargo build --features llvm
python3 scripts/corpus/run.py --backend legacy          # each program on the backend it was recorded on
python3 scripts/corpus/run.py --backend legacy --exclude core --exclude drop-matrix   # M0 check: 0 FAIL
python3 scripts/corpus/run.py --backend legacy-build --filter drop
python3 scripts/corpus/run.py --backend legacy-interp --filter fixtures/interpreter/ --quiet
```

`core/` and `drop-matrix/` hold v2 expectations that legacy is meant to miss
(on legacy the matrix passes only its 28 programs where the model and legacy
already agree), which is why the M0 check leaves them out; every other entry
is held to legacy's own recorded output.

`--filter` takes a tag or a path substring. The runner pins
`KARAC_HASH_SEED=1`, prints one `PASS|FAIL|SKIP` line per program, a summary by
class and by tag, and how many programs actually executed. It exits 1 on any
FAIL and 2 when nothing executed, so a filter that matches nothing cannot read
as a pass. `mir-interp`, `mir-llvm` and `mir-llvm-asan` are named slots that
SKIP until the new pipeline exists.

## Rebuilding

```bash
python3 scripts/corpus/extract.py --katas ../kara-katas    # sources -> source.kara + meta.toml
python3 scripts/corpus/record.py                           # one legacy run + check per new program
python3 scripts/corpus/record.py --recheck --filter <path>  # mark a program nondeterministic if a re-run differs
python3 scripts/corpus/record.py --model                    # drop model output per program (model.out, model_verdict)
```

`extract.py` also regenerates the drop matrix from `corpus/tools/drop-model/`
(`--no-matrix` leaves it out) and copies each program's model output to
`expected.out`. `extract.py` reads the test files and never edits them. It keeps each
holding test's string literals as candidate expectations, and `record.py`
marks a program `expected_from = "assert"` only when one of them matches the
legacy run as the suites compare (exactly, trimmed, or line by line); the
rest are `legacy-run`, most of them IR-shape tests that assert nothing about
stdout. Re-extracting keeps every unchanged program's recorded files and
drops them for any program whose text changed. Raw logs of the recording
(check JSON, stdout, stderr) stay under `target/corpus-work/logs/`.

Outside `core/` and `drop-matrix/`, a program has no `expected.out` until it
is classified, and the runner holds it to `legacy.out`: a measured baseline of
OLD behaviour, not a specification. Classification against the MIR
interpreter writes `expected.out` per class, so the diff shows every program
whose expectation moved.

## The drop model's output

`record.py --model` runs `corpus/tools/drop-model/kmodel.py` over every
recorded program outside `core/` and `drop-matrix/`. For model_verdict SAME,
ORDER, ORDER-UNSPEC and DIFF it writes `model.out` and sets `model_verdict`,
`model_exit` and `model_rev` (an md5 prefix over the model's `.py` files; a
re-run redoes only entries at another rev). A V2-REJECT gets `model_verdict` and
`model_note` (the rule broken on the executed path) and no `model.out`. UNSUP,
PARSE, CRASH and LEGACY-REJECT get only `model_rev`.

On the mir backends `run.py` takes the expectation from `expected.out`, then
`model.out` (held to `model_exit`; ORDER-UNSPEC compares lines as a set), then
`legacy.out`. A V2-REJECT program is not run: `karac check` must refuse it, and
when check accepts it the verdict is MREJ, "model rejects, check accepts",
counted on its own. MREJ needs only `karac check`, so it is judged before any
mir backend exists. The legacy backends ignore all of this.
