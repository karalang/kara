- L190-L216 (`decide`) and L220-L259 (`record`): the natural `map.entry(key).or_insert(default)` (returns `mut ref V`) does not work in codegen when V is a struct (interp is fine). Three forms failed: (a) `let bucket = m.entry(k).or_insert(..); bucket.can_take(..)` -> `codegen: no handler for method 'can_take' on variable 'bucket'`; (b) `let stats = m.entry(k).or_insert(..); stats.total += 1` -> `codegen: cannot resolve field 'total' on this receiver (its type was not recorded for codegen)`; the same with a `: mut ref ClientStats` annotation; (c) chaining `m.entry(k).or_insert(W { .. }).has_room(2)` builds but the binary SEGFAULTS (an 8-line program with a 2-field struct reproduces it). The client-quota check moved into a free fn `admit(quota: mut ref TokenBucket, req)` as part of that rewrite.
- L171-L176 (`handle`): a helper `fn policy_for(ref self, route: ref String) -> Result[Policy, LimitError]` called as `self.policy_for(req.route)?` (where `req: ref Request`) builds but the binary aborts at exit with `free(): double free detected in tcache 2`, and all buffered stdout is lost. The interp is fine. Minimal repro: `struct Req { route: String }`, `impl L { fn check(ref self, route: ref String) -> i64 { 1 } }`, `fn handle(l: ref L, req: ref Req) -> i64 { let p = l.check(req.route); 2 }`, called over a `Vec[Req]` whose `route` came from `split(..)[1].clone()`. A free function with the same signature does not crash, and neither does a string-literal field. Workaround: I inlined the lookup into `handle`, so no user method receives `req.route`.
